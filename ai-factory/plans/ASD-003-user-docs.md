## Design

- **Reader.** `skills/ai-layout/scripts/_frontmatter.js` exports one function that takes markdown text and returns the frontmatter keys as strings: only the block between the first two `---` lines, never a match elsewhere in the file. It requires only `node:` built-ins, has no top-level side effects, and writes nothing (AC9, AC10). `sync-claude-commands.js` and `sync-codex-skills.js` are not moved onto it (R4, out of scope).
- **Generator.** `skills/ai-layout/scripts/sync-docs.js` follows `sync-claude-commands.js`. `root` is `path.resolve(__dirname, "../../..")`, so a fixture can copy the two scripts into a scratch tree and run them there. It has one `emit(file, body)` that writes, or with `--check` compares and records a failure. `--check` collects every failure, prints each one naming the file, link, heading or version, and exits 1 at the end. It never writes.
- **Classification (AC13).** `<name>` is a project task when `skills/ai-layout/templates/ai-factory/tasks/<name>.md` exists (18: including `quick`). Otherwise it is a plugin-level command (7). `check` is plugin-level by that rule, and its page also says it is the deprecated alias of `/fc:review` and links `review.md` (AC16). Arguments come from `argument-hint` in `commands/<name>.md`; for a project task, from the task frontmatter when the command has none. With neither, the page says "none". Codex name: `$fc-<name>`.
- **Page layout.** Each `docs/commands/<name>.md` has a generated header (title `/fc:<name>`, a back link to `../commands.md`, a "Generated by … do not edit; edit `_notes/<name>.md`" comment, then a field table: Claude name, Codex name, kind, description, arguments). The notes file follows verbatim. The generator never rewrites the notes' links, so a link to `../../ai-factory/docs/workflow.md#…` passes through (AC18).
- **Index.** `docs/commands.md` is generated: intro, counts derived from the files, then the group table and per-group tables of name, arguments, kind and description. The group table, which is hand content, lives in `docs/commands/_notes/_groups.md`. The generator reads that file for the group order and membership. A command in `commands/` that is in no group fails `--check`. The draft's "What it does" column is replaced by the description, and the draft's "Writes" column moves into each command's `## Writes` notes (AC17).
- **Prune (R3).** After a write run, the generator deletes only regular `*.md` files directly in `docs/commands/` with no matching `commands/<name>.md`. It uses no recursion, never enters `_notes/`, and never touches non-`.md` files (AC20). `--check` reports such orphans instead of deleting them.
- **Notes structure (AC15, AC24, AC25).** A heading counts if it is an H2 line exactly `## Usage`, `## Examples`, `## Writes` or `## Refuses or asks`. Its content is the text up to the next `## ` line or end of file, and only whitespace counts as empty. `check.md` needs only `## Usage`.
- **Links (AC26–AC30).** `--check` scans every `*.md` under `docs/` (including `_notes/`, since the notes are content) and the root `README.md` links whose target is under `docs/`. It checks inline `[text](target)` links, ignoring `http(s):`/`mailto:` links and any link inside a fenced code block except Mermaid `click` lines. Each target is resolved against the page's directory. A target that resolves outside the repository root fails whether it exists or not (R8). A missing target fails. A `#fragment` is matched against the GitLab anchors of the target's headings. A link in `_notes/<name>.md` is resolved as it will be rendered from `docs/commands/<name>.md`, so authors write paths relative to the generated page. Say so in `_groups.md`'s leading comment.
- **GitLab anchors.** Slug = heading text, lowercased; drop every character that is not a letter, a digit, a space, `-` or `_`; spaces become `-`; repeated slugs get `-1`, `-2`, …. The developer accepted this rule. The Step 1 spike did not separately confirm it on the host (see `## Spike result`), so the anchor check relies on this rule as stated, and the `links` fixture cases in Step 4 pin it.
- **Version line (AC4, AC31, AC34).** Line 3 of `docs/README.md` must be exactly `> For fc ai-sdlc <version>.` with `<version>` from `.claude-plugin/plugin.json`. `--check` checks it. `check-versions.sh` adds `docs/README.md` to the versions it compares, as one more `found` row parsed from line 3 by that regex. If line 3 does not match, it records the line as found and fails.
- **No tests runner.** This repo has none. Behaviour is pinned by a new fixture check, `skills/ai-layout/scripts/check-sync-docs.sh [group]`, modelled on `check-ids.sh`. It builds disposable trees under `ai-factory/runs/tmp/`, copies `sync-docs.js`, `_frontmatter.js` (and in the `versions` group `check-versions.sh`) into them, and runs them there, never against the real `docs/`. Groups: `reader`, `generate`, `prune`, `check`, `notes`, `links`, `versions`; the default is all. A case whose script or export is missing fails as that case, not as a crash. Being a `check-*.sh`, it joins the checks loop (AC40).

## Decisions (accepted by the developer, 2026-10-30)

These were the planning ambiguities of the first draft. The developer has settled them, so they are no longer open:

1. **Fixture check.** `skills/ai-layout/scripts/check-sync-docs.sh` is an extra `check-*.sh` that runs the generator against throwaway copies under `ai-factory/runs/tmp/`.
2. **Group table.** It lives in `docs/commands/_notes/_groups.md`. That file is not a command's notes file.
3. **Links inside notes files.** Authors write them, and `--check` resolves them, as they appear in the generated `docs/commands/<name>.md`.
4. **GitLab heading slugs.** The rule under *GitLab anchors* is accepted. The spike did not separately confirm it, so the anchor check relies on the stated rule.
5. **`/fc:check` is plugin-level.** A command is a project task only if a task template of that name exists, which gives 18 project tasks and 7 plugin-level commands. The `check` page is marked deprecated and points to `/fc:review`.
6. **AC36 and AC43 evidence.** It is kept in this plan's `## Spike result` section and in the MR text that Step 11 prepares.
