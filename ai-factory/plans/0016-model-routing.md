# Plan 0016 — Automatic model selection for CLI and interactive sessions

**Status:** Complete. Steps 1–7 are checked off. Step 7 was marked complete by the owner on 2026-10-05 without the opt-in real-host smoke runs; interactive routing on each host remains implemented but unverified until those runs are captured.

**Goal:** Resolve a per-task model from `ai-factory/models.yaml` once, and enforce it for headless runs and interactive tasks, never falling back to another model.

**Spec:** `ai-factory/specs/0016-model-routing.md`

**Branch:** `feat/model-routing`, prepared as 2.8.0.

## Host adapter matrix (Step 1, 2026-09-30)

| Question | Claude Code 2.1.285 | Codex CLI 0.153.2 |
|---|---|---|
| Per-task pin | Project agent `.claude/agents/<name>.md`, frontmatter `model:` (documented: aliases, full IDs, `inherit`) | Project agent `.codex/agents/<name>.toml`; a non-empty `name`, `description` and `developer_instructions` are required (read from the binary's loader messages) |
| Per-call model | Agent tool `model`, an alias enum (observed in the host's own tool schema) | `spawn_agent` `model`, limited to the models the host lists (binary strings) |
| Precedence risk | `CLAUDE_CODE_SUBAGENT_MODEL` overrides every subagent's model (documented) | An agent file's settings win over the spawn request (owner's reference); a full-history fork inherits the parent agent type (binary message) |
| Reload | Agent files load at session start | Agent files load at session start (assumed; not documented) |
| Arbitrary gateway alias in the pin | Unverified | Unverified |

Design consequences:
- Pins go in generated, content-addressed agent files, not in per-call overrides.
- Claude dispatch stops when `CLAUDE_CODE_SUBAGENT_MODEL` is set.
- Codex workers are spawned with `fork_turns` `none` and no `model`.
- No bridge is built, because both hosts have a native mechanism.

## Implementation sequence

- [x] **Step 1 — Validate host capabilities and pin the contract.** AC1–AC7.
  - The matrix above.
  - Fixtures for both tools: routing enabled, disabled and absent; overrides; blank values; review normalization; custom tasks; expected sources.

- [x] **Step 2 — Extend configuration parsing.** AC1, AC2, AC7, AC10.
  - `make/models.js`, a strict two-space subset with line-specific errors. It rejects tabs, flow syntax, duplicates, unknown keys, `review` under tasks, and non-literal booleans.
  - `pricing` is read exactly as before, and the hooks' price reader still reads it.
- [x] **Step 3 — Resolve by canonical task.** AC2–AC6.

- [x] **Step 4 — Apply and record selection.** AC3, AC8, AC9, AC12.
  - Before launch: the runner prints a stderr selection line, and refuses to start when `CLAUDE_CODE_SUBAGENT_MODEL` would override routed subagents.
  - After launch: a `.model.json` sidecar records success or failure. No retry.
  - **Verify:** `check-runner-security.sh`, `check-review-scope.sh`.
- [x] **Step 5 — Implement interactive dispatch adapters.** AC13–AC17.

  - **Verify:** `check-interactive-model-routing.sh`.

| Risk | Check |
|---|---|
| Ambiguous override precedence | The resolution matrix in `check-model-selection.sh`, and the argv checks through Make in `check-runner-security.sh` |
| The custom YAML subset accepts a typo | 28 rejected configurations, each asserted by line |
| A stale native binding runs the old model | Content-addressed names: an edited mapping yields a new agent; dispatch compares the file byte for byte |
| Claiming more host control than verified | The matrix above marks what is unverified; the workflow guide says so; Step 7 records the waived smoke runs |
| The chat does the task itself | Directive text, a worker that forbids redispatch, and the Codex fallback limited to the legacy and inherit directives. Prompt behavior itself is only provable by a host smoke run |
