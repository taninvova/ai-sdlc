Notes on categories with no finding of their own:
- Authorization: the watcher reads local files under the developer's own checkout and writes nothing (AC53–AC55). No access path, permission or hook changes (AC62). `/fc:watch` appends the developer's own argument to a shell command the model runs, as `commands/state.md:19-38` already does for `/fc:state`. That is the developer's own input in their own shell, not a privilege boundary.
- Secrets: the feature reads, writes and passes no credential. Secrets that an agent echoed into its saved output are covered under R5.
- The loop ID argument is checked against `LOOP_ID` (`skills/ai-layout/templates/ai-factory/make/loop.js:1352-1355`) before it becomes a path (AC13). That closes path traversal through the argument, but not through the make variable that carries it (R1).

## Residual risks
- The watcher lives in the scheduler's file, so any later change to the view is a change to the file every `/fc:loop` in every adopted repo runs through (R6). Only checks, not separation, keep the two apart.
- The live-mode criteria (AC46–AC48) stay partly proved by a platform-specific terminal harness or by injected TTY state, not by a real terminal on every platform (R8).
- Character stripping is a deny-list. A terminal that acts on a character not on the list would still act on it (R2, R3).
- Saved agent output shown with `--details` remains untrusted text. Docs and the command prompt reduce, but do not remove, the chance that it is pasted into a CI log or acted on in a session (R5).
- `--follow` on a loop that never records `ended` waits until it is killed (R10), unless the developer decides otherwise in the spec.
- Delivery stays sequenced on ASD-006, which is not yet planned (R7).
