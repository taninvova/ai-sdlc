Notes on categories with no finding:
- Authorization: the Claude wrapper (`skills/ai-layout/scripts/sync-claude-commands.js:23-25`) carries no `allowed-tools` and dispatches the target task with `entryPreamble(<host>, <target>)`, so a shortcut gets exactly the target's tools, worker and permissions (AC4, AC7, AC15).
- Data exposure and secrets: no new data, credential or env var is read or written; `.task.<session>` keeps the canonical name (AC21).
- Migrations: no recorded run-log row, lifecycle event or routing record is rewritten; readers canonicalise at read time (`make/cost.js:189-195`, `make/lifecycle.js:79,380`).
- Injection: shortcut names are fixed table entries; `canonicalTask` uses `Object.hasOwn` (`models.js:24-25`), and the runner and dispatch validate the canonical name against `^[a-z][a-z0-9-]*$` before building a task path (`runner.js:295-298`, `models.js:480-482`). One minor finding below (R7).

## Residual risks
- After the mitigations, three new names are permanently part of the public `/fc:`, `$fc-`, `TASK=` and `routing.tasks` namespaces. Removing one later is at best a deprecation, never a clean delete (R3).
- Adopted repos keep a window where plugin entry points accept a shortcut but their unsynced `make ai` and `models.yaml` do not (R4). Only `/fc:sync-sdlc` closes it, and this plugin keeps no registry of adopter versions to tell who has synced.
- The hook's table remains a pinned copy that a fixture keeps equal to `models.js` (R5). Drift is caught when the checks run, not when the code runs.
- Labelling a session by a command mentioned anywhere in the prompt, rather than only at its start, remains unless the hook's regex is changed (R7).
