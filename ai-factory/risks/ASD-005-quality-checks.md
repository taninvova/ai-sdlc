Notes on categories with no finding:
- Authorization: no user, role or permission model is touched. `quality.json` lives in `ai-factory/`, so anyone who can edit it can already edit plan `verify` argv, which `make verify` executes today (`skills/ai-layout/templates/ai-factory/make/contracts.js:1167-1169`). The trust boundary does not move.
- Secrets: no credential is read or written. Checks inherit the process environment, as `execute()` does today (`contracts.js:1131`, no `env` override). R9 covers secrets that a tool prints.
- Migrations: no existing evidence is rewritten (AC38). The data-shape risk falls under rollback and blast radius (R5, R6).

| R1 | injection | major | open | skills/ai-layout/templates/ai-factory/make/contracts.js:317 | AC12 refuses a check "on the same rule that `Verify` commands follow today". ## Residual risks
- Repo-declared argv still runs with the developer's or CI's full environment and privileges, as `Verify` does today. Running without a shell removes shell injection but not what the declared program itself does (R1, R2).
- Correct tool results depend on third-party CLIs and flags outside this repo's control. Version staleness reveals an upgrade only after the fact (R10).
- Quality evidence breaks validation on any machine still on a 5.x plugin, until every validator in the repo's toolchain is on 6.0.0 (R5).
- Until a later slice gates on quality evidence, a failed or skipped required check is information only, and the commit-then-not_run path (R4) remains unless AC13 or AC17 changes.
